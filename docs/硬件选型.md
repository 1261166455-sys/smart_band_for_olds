- MCU 选型 (需要讨论)

  - **方案一: 选择牢学长同款 STM32F411CEU6 主控**

    1. 优势是有前人经验可以参考, STM32 相关资料偏多, 这是热门主控, 相对好买

    2. 但对于我们的需求 (需要处理双向蓝牙音频数据 + LVGL 驱动触控, 彩屏的 UI 界面, 他的 128KB RAM 不太够用, 而且需要外挂蓝牙组件/手写音频编解码相关驱动和协议)

  - **方案二: 选择 ESP32-WROOM-32E-N8 主控**

    1. 优势是 ESP32 系列主控拥有更强的处理器, 板载蓝牙和Wi-Fi模块, 更大的 RAM 和 Flash 闪存, 可以实现更复杂的交互逻辑和 UI 界面, 降低编写各种复杂驱动/纠结内存的代码 (主要是我们语音助手的需求相对复杂, 需要编解码音频数据, 对于控制器的要求更高), 也算比较热门的主控

    2. 缺点一是没有前人支持了 (当然也有可能学长和老师很了解也说不定, 不过 ESP32 和 STM32 是几乎完全不同的两套逻辑)

    3. 缺点二是蓝牙音频传输部分由社区维护的一个库支持, 现在不太能100%保证这套技术栈能跑通, 需要实验和进一步研究

  - **方案三: 选择 STM32WB55CGU6 主控 (不推荐)**

    1. 是这套方案是AI给的综合最优解, 这个芯片的确解决了性能的问题, 相比方案二也有非常成熟的音频链路处理方案

    2. 但一个严重缺点是这个主控比较冷门, 几乎买不到现成的开发板, 只能买到主控芯片本体, 意味着我们大概率要手画 PCB 板, 自行打板焊接处开发版和最终的成品, 上手难度很高, 我个人觉得上手难度太高了
